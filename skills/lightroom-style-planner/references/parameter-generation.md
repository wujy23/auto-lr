# 参数估计与控制项检查

用于将已确认的画面关系、当前显影状态和联合设计的全局/蒙版方案转为具体参数。先按 [色彩与影调分析](tone-color-analysis.md) 识别主要问题，再选控制、估计数值，最后检查所有常用项目是否遗漏；只有确有必要的项目进入写入清单。“保持”必须保留当前值，不能替换为零或默认值。

以下按工具分类便于查阅，不规定思考顺序，也不代表 Adobe 内部渲染管线。完成方案后集中执行、轮末统一检查，不逐项写入、导出或询问。

## 1. 输入、状态和记录方式

读取本轮预览、处理版本、配置文件、白平衡、基本参数、完整四条点曲线、参数曲线、八色 HSL 和相关蒙版。未知值标记未知，不能把计数当成曲线内容。风格目标以用户确认版本为准，已有曲线和蒙版是当前画面的一部分。

修改项记录：`关联问题 → 控制项 → 当前值/结构 → 作用范围 → 估计依据及置信度 → 最终绝对值/结构 → 预期效果与保护项 → 实际接口 → 检查标准`。有可用依据才写候选区间。保持项简记当前值、保持结论和原因；不适用或数据不足单独标明。无需为每个不改的控件重复展开完整问题卡。

每项可以承担主要修正、辅助修正或保持。先确定本轮主要承担者，再估计其他工具尚需承担的量。分工只是待验证策略；渲染后若未达目标，允许重选工具、撤回部分调整或再次优化同一字段。例如降低阴影并压低主曲线暗段时，二者不能各自承担一份完整的压暗目标。

用户准确指令优先；否则用同图或条件可比的历史渲染响应辅助估计，没有记录时从当前值、差异和保护边界给出可执行初值，并标注视觉估计。初值不是已证实的最佳值。本规范不提供跨照片固定步长；工具值域是合法性边界，不是效果强弱标尺。

## 2. 前置检查：配置文件、白平衡和模式

- 判断偏色是整体白平衡问题、分区风格要求还是场景真实光色。可信中性色可以作锚点；日落云层和有色灯光下的白物体不默认中性。
- 已有配置文件与白平衡经当前画面和目标验证为合理时保留；确需变化时先确定它们，再估计后续颜色参数。不要一边加暖白平衡、一边用多条曲线把同一区域抵消回去。
- RAW 与 JPEG 的色温控制、SDR 与 HDR 的影调表现不能直接套用同一数值约定。记录当前模式，按实际接口与范围处理；不自动切换配置文件或输出模式。

## 3. 基本影调：六个控制的分工

| 控制 | 从当前图判断什么 | 调整方向的条件 | 与其他控制的分工 |
|---|---|---|---|
| 1. 曝光 | 主体和主要中间调是否整体偏暗/偏亮；不同区域是否同向偏离目标 | 普遍偏暗才增加，普遍偏亮才减少；仅前景偏暗而天空合适时优先局部处理 | 定整体明度基准，不用全局曝光单独救阴影或塑造黑位 |
| 2. 对比度 | 整体明暗分离是否不足或过硬，黑白端是否已经紧张 | 需要宽范围、近似对称的反差变化时调整；只需改变某一影调段时保留或减小幅度 | 与主曲线明确谁负责主要反差，不机械同时增加 |
| 3. 高光 | 云层、皮肤反光、夕阳等亮部是否缺层次，还是压得灰闷 | 过亮且有可恢复层次时降低；已被压灰且目标需要亮部活力时适量增加 | 处理亮部层次；白色处理亮端锚点，曲线处理高光过渡形状 |
| 4. 阴影 | 暗调对象是否可辨、是否发灰，是否丢失暗色体积 | 堵塞且需可读时增加；过度提亮、缺乏深浅关系时降低 | 保护深黑缝隙；不同对象需求冲突时交给蒙版 |
| 5. 白色 | 最亮区域是否有应有的亮度和跨度，是否出现不必要的截断 | 亮端不足时增加，溢出且不符合意图时降低；纯白背景或点光源按题材判断 | 不以“直方图必须顶到最右端”为目标，不重复补偿高光 |
| 6. 黑色 | 最深区域是否深实，关键纹理是否被吞没，是否有不必要的灰底 | 黑位发灰时降低，重要暗纹理被截断时适度增加 | 区分深黑与阴影可读性；雾面黑位的曲线端点单独设计 |

数值依据优先采用可比区域的明度分位点、亮暗占比、原有设置和视觉保护条件。未实际测量时明确标为视觉估计。显示预览的截断不能证明 RAW 信息已不可恢复。

检查六项的共同作用：主体明度、整体反差、亮部层次、暗部可读性、黑白端是否同时满足目标；冲突先修正职责和数值，不靠曲线不断抵消。保留有意的亮暗面积与视觉重点，不以所有区域细节同等可见为验收标准。

## 4. 空气感与细节：去朦胧、纹理、清晰度

- **去朦胧**：判断是否确有遮蔽层次的雾感，还是低反差、逆光或远景空气透视。需要去雾时正向，目标更柔和或需保留雾感时保持或负向。近景需清楚、远景需柔和时优先局部控制。
- **纹理**：按材质判断细节是否不足；木纹、岩石与皮肤不能采用相同强度。它不替代失焦恢复。
- **清晰度**：判断局部明暗过渡是否需要加强或柔化；留意高反差轮廓的亮边、阴影加重和材质变硬。
- 三项分别记录判断，不把“通透”翻译为全部增加。已有局部调整也纳入初值估计，远景柔和、近景清楚可以是有意保留的关系。
- 将对比度、曲线、去朦胧及清晰度对整体观感的共同作用列入检查，尤其留意颜色变浓、阴影变重和距离感被消除。软件行为参见 [Adobe 影调与颜色控制](https://helpx.adobe.com/lightroom-classic/desktop/process-and-develop-photos/image-tone-color.html)；具体分工与检查方法属于本项目设计。

## 5. 四条曲线：主 RGB、红、绿、蓝分别给出结论

四条指主 RGB 点曲线与 R/G/B 三条通道点曲线。参数曲线另行读取并纳入共同作用检查，不把它误计为四条中的一种。主 RGB 也不等同于完全不影响颜色的纯亮度曲线。

### 5.1 主 RGB 点曲线

依次审查黑端、暗调、中间调、亮调、白端，决定每段保持、上移、下移、变陡或变缓，并说明锚定段。

- 要更强反差时，在受保护的中间调附近安排适度 S 形；实际渲染证明现有反差已符合固定目标时可以保持；“已调整基本参数”本身不能证明反差足够。
- 要暗调可读但保留深黑时，考虑抬升相关暗段而锚定黑端，不把黑点整体上抬当成唯一办法。
- 要雾面观感时才考虑抬高黑端；若目标为深实黑位，不因“胶片感”标签默认抬黑。
- 要柔和亮部时关注高光段斜率与过渡，不直接把白端压低导致所有亮部发灰。
- 以当前控制点为基础提出修改。曲线候选来自当前与目标的影调差异，不把参考图直方图匹配结果直接当作 LR 点曲线。

### 5.2 红、绿、蓝通道曲线

| 通道 | 输出上移的颜色倾向 | 输出下移的颜色倾向 | 必须评估的内容 |
|---|---|---|---|
| 红 | 增加红色成分 | 相对偏青 | 暗部是否过红/过青；中性与肤色保护；暖亮部是否已由其他工具负责 |
| 绿 | 增加绿色成分 | 相对偏洋红 | 草地与中性色是否混淆；阴影绿偏；肤色和云层是否被染色 |
| 蓝 | 增加蓝色成分 | 相对偏黄 | 暗部冷暖、亮部黄蓝关系；天空与白云的颜色过渡 |

上述是其他条件相同下的相对倾向，不是固定风格配方；三通道共同决定颜色与亮度。通道曲线按该通道输入值起作用，所谓“低段”不严格等于统一亮度定义的阴影，也不只影响同名颜色对象。仅天空蓝色有问题时，应优先评估 HSL/天空蒙版，而非默认修改蓝通道曲线。

每条分别给出：当前曲线、需要改变的输入段、变化方向与程度、保护锚点、候选完整点列或保持理由。需要冷暗部暖亮部时，先检查已有通道曲线和色彩分级是否已实现；二者分配主要与辅助职责，避免重复染色。

### 5.3 点列与数值生成规则

- 统一记录坐标制。以 0–255 的分析坐标描述时，可用约 0、32/64、128、192/224、255 作影调段讨论锚点，但不能不看现有曲线就插入这套点或重置端点。
- 少量必要控制点即可。保持输入有序、输出平滑，默认不制造非单调反转；防止过密控制点、陡折、重复输入点和局部压缩导致断层。所用 LR 插值与处理管线可能使实际效果不同，最终以渲染为准。
- 位移依据当前点列、目标输入段及邻段保护要求估计；同样的控制点位移在不同原曲线和图像上不保证产生相同观感。不要用固定点差代替画面判断。
- 完整读取现有曲线；生成最终绝对点列并保留未改变的结构。记录旧点列、新点列及变化原因，不把“叠加修正曲线”误当作“覆盖为新曲线”。
- 四条曲线即使不改，也必须各有“保持当前＋原因”的记录。曲线有必要改变但接口不支持时，标为执行能力缺口，不能写成审美上无需修改。

## 6. 颜色总量：饱和度与自然饱和度

先判断全图颜色是否普遍偏浓/偏淡，还是仅特定色相突出。全局确有问题才估计总量调整；局部问题留给 HSL/蒙版。饱和度与自然饱和度效果不同，不当作可直接互换的数值。

将白平衡、通道曲线、去朦胧及色彩分级的颜色影响一并考虑，不把所有工具独立估计的去饱和量同时叠加。主体颜色弱时先核对环境的面积、明度和彩度，允许通过收敛环境达到突出主体的目标。

## 7. HSL：八个色相逐个检查 H、S、L

每个色相先标出它在待修照片中的对象和面积，再分别判断色相偏移、彩度及明度；不能只输出“绿色降低一点”。以下对象仅为排查提示，必须以实际图像为准。

| 色相 | 常见排查对象 | 特别关注 |
|---|---|---|
| 红 | 暖光、衣物、招牌、肤色部分 | 强调色与肤色是否冲突 |
| 橙 | 肤色、夕阳、木材、暖色岩石 | 改夕阳是否同时改变木材或肤色 |
| 黄 | 草地受光面、枯草、暖光 | 与橙、绿的过渡是否自然 |
| 绿 | 植被、部分阴影或物体表面 | 叶片深浅、受光与背光面、与黄色衔接 |
| 青 | 水面、蓝绿物体、反光 | 同色干扰物与天空/水面是否需分开 |
| 蓝 | 天空、水面、冷色阴影 | 饱和度、天空渐变及蓝色明度同时下降是否过重 |
| 紫 | 暮色、阴影、花朵或染色 | 是真实场景颜色，还是需要修正的局部偏色 |
| 洋红 | 晚霞、花朵、衣物、肤色部分 | 是否应作点缀，是否污染中性或肤色 |

每一行都填写 H/S/L 的当前值、判断与目标值；未见该色相也只记为保持或不适用，不自动清零。颜色分类有重叠，不能把每个滑块看成互不影响的精确分割。

- **H 色相**：先说明朝哪个邻近色相移动，再结合实际滑块方向转换为正负值，不把角度直接写成滑块点数。
- **S 饱和度**：判断颜色是否抢眼或缺乏表现，不用增加饱和度代替提亮；彩度减少 20% 不等于滑块 −20。
- **L 明亮度**：判断该色对象应更亮还是更深，不把明亮度当作不影响其他色彩关系的曝光工具，注意噪点、断层和边缘。
- 同色对象需求冲突时改为区域受限的局部控制；全局 HSL 会影响照片中其他相同色相区域。工具定义参见 [Adobe 颜色混合器说明](https://helpx.adobe.com/lightroom-classic/desktop/process-and-develop-photos/color-mixer.html)，本节对象检查表是本项目方案。全局 HSL 可用不代表连接支持局部 HSL；局部须选实际存在的控制。

## 8. 色彩分级与局部参数

按暗部/中间调/亮部的冷暖关系评估色彩分级，它可以是主要工具，不必先叠加四条曲线与 HSL 再使用。确有需要时记录各区色相、强度、平衡和混合；与通道曲线指定明确分工，不因有参考图就同时添加全部染色工具。

对每个设计蒙版检查相关的局部明度、反差、亮暗层次、颜色与质感。全局与蒙版联合规划，按预期合成状态分配修正量；这是推演而非已渲染测量，必要时在轮末纠偏。某种控制只在全局可用时，不虚构对应的局部字段。

蒙版覆盖面积、羽化、范围筛选及重叠会影响效果。与已有局部设置合并后生成目标绝对值，区分 LR 显示单位和存储单位。

## 9. 完整评估表、执行子集与验证

`parameter_review` 保存完整覆盖检查，至少覆盖六项基本影调、去朦胧/纹理/清晰度、四条曲线、饱和度/自然饱和度和八色各 H/S/L。色彩分级和相关局部控制也给出采用或保持的结论。四条曲线用结构化点列记录，不能塞进标量变化量列。保持项可引用本轮已保存的完整基线，但八色 H/S/L 和四条曲线的结论不可遗漏；该表不是要求所有控件都改变。

面向用户展示关键参数变化和重要保持理由；完整评估存入本轮记录。执行子集分别放入 `settings`（全局数值）、`curves`（四条点曲线）、`masks`（受支持的几何蒙版），具体格式见 [执行计划字段规范](execution-plan.md)。`parameter_review` 和 `mask_plan` 是说明记录，不会被 apply 自动转换为操作。

同一字段只生成一个最终目标值。写入前检查：曝光/阴影/主曲线是否重复提亮，对比度/黑白场/去朦胧是否过度强化，RGB 曲线/分级/HSL 是否重复染色，全局与局部是否合力损伤保护区。无效、未知或不支持的必要操作不得伪装为已执行。

整轮完成后分开记录执行核对与视觉评价：前者验证实际数值，后者逐条判断关键目标是否改善及保护项有无损伤，不能互相替代。视觉检查包括主体与背景关系、黑白端细节、天空和肤色渐变、中性色、噪点与光晕、前后距离。保留集中修改和轮末预览的节奏；不为完整检查而逐项导出。纠偏根据观察到的剩余差异选择少数主要控制，不把第一轮数值机械倍增；最多两轮，未达目标如实记录。
