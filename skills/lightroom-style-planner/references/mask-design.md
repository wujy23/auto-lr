# 蒙版设计规范

用于从参考图与待修图的区域关系推导局部控制方案。与全局参数联合设计，不作为固定的最后补救步骤；区域意图提前进入风格说明卡，便于用户集中确认。

## 1. 区分观察、推测与真实蒙版

- 参考图只有 JPEG/PNG 等成片时，可观察亮暗、色彩、纹理及过渡位置，推测哪些区域适合独立控制；不能恢复或声称读到了作者的真实蒙版、羽化或参数。自然光、材质和拍摄条件也能形成同样效果。
- 参考素材包含可访问的 LR 显影设置或侧车数据时，检查其中实际可读取的蒙版类型、结构、启用状态与调整；缺少 AI 选区数据或相关资源时标记不完整。存在蒙版元数据不等于能完整重建选区。
- 为参考区域记录：位置与对象、可见效果、可能的局部调整方向、其他合理成因、推断置信度。统一标注 `observed`、`inferred` 或 `read_from_edit_data`。
- 从参考图迁移“视觉角色与区域关系”，不直接复制坐标。例如参考图的亮河流是视线引导，目标图对应的引导元素可能是道路、受光边缘或夕阳亮带。

## 2. 先判断是否需要蒙版

针对待修照片分别检查当前预览、已有蒙版及其调整。已有选区合适时优先复用；不因名称相似就认定覆盖范围正确。

当不同区域需要相反处理、同色对象需要分别控制、需要沿空间渐变调整，或全局调整会损伤保护区时，采用局部蒙版。若全局或颜色控制已经可以完成目标且不影响其他区域，可明确写“无需新增蒙版”。不为了形式给每个物体建立一个蒙版。

蒙版目标绑定已识别的画面问题：例如“降低草地相对小屋的视觉竞争”，而非只有“草地 −10”。明确本蒙版是主要还是辅助修正，以及全局方案已承担什么；参数增量不能与全局修正简单相加来预测实际效果。

同一范围需要不同调整组合时使用独立的调整组；同一调整组的添加、减去或交集组件只共同决定覆盖范围，不各自承载独立曝光值。方案应说明是“修改同一选区”还是“另建一组调整”。

### 多人照片：避免新建单人或部分人物选区

当前纯 SDK 工作流尚未验证可靠的人物候选枚举和指定人物创建。目标照片包含多个人物时，不规划新建只覆盖其中一人或部分人物的蒙版，包括指定人物的面部皮肤、身体皮肤、头发、衣服等；不要通过换用 subject、径向蒙版或空间交集变相实施这类定向新建。也不尝试用人物编号、ReferencePoint 或不同蒙版 ID 来保证选中了不同的人。

- 在 define_goal 阶段就遵守此限制：用户未要求单独处理某人时，优先制定人物整体协调、肤色自然、人与环境关系等可执行目标，不自行加入“只提亮左边的人”等验收项。
- 优先复用已有且覆盖范围已确认的蒙版。已有单人/部分人物选区可继续调整局部参数，使用 editable_masks 的真实 ID，保持覆盖不变；名称、单个参考点或“检测成功”不能单独作为覆盖确认。
- 需要新建时，只采用当前正式能力明确支持、且作用范围符合目标的方案。全人物或全人物部位选区也必须实际可执行；独立实验成功不等于正式入口已支持。subject 不保证包含所有人物，不能直接等同于“全人物蒙版”。
- 若没有可用的人物整体选区，优先评估现有蒙版、全局/颜色控制或环境调整能否在不损伤保护项的前提下完成目标；并非必须创建人物蒙版。不要自动转向 computer use 或把流程依赖于临时人工选人。
- 纠偏同样遵守本规则。在 mask_plan 简要记录多人限制与本轮可执行策略。只有固定目标或用户明确要求必须单独处理某人、且没有覆盖已确认的现有选区或其他合规可执行方案时，才报告具体能力缺口；不能暗中扩大作用对象或降低已确认目标。

## 3. 类型选择与必要信息

以下是设计选择建议。软件支持的蒙版类别与组合能力参照 [Adobe Lightroom Classic 蒙版说明](https://helpx.adobe.com/lightroom-classic/desktop/process-and-develop-photos/masking.html)，具体可用性以本机版本和当前连接为准；本表不是 SDK 支持清单。

| 选择方式 | 适用目标 | 设计时给出的信息与限制 |
|---|---|---|
| 线性渐变 | 天空向地平线、画面边缘或前后景的渐进变化 | 渐变方向、起止位置、过渡宽度、强弱端；复杂地平线需结合天空/对象限制 |
| 径向渐变 | 柔和强调局部、受光区域或收敛周边 | 中心、宽高、旋转角、羽化、作用内部或外部；不默认用椭圆代替复杂对象边界 |
| 主体、天空、背景、对象 | 需要按语义对象分离的局部调整 | 目标对象及位置；对象提示框/笔触；需保留的孔洞和边缘；生成后核对误选漏选 |
| 人物、风景分类 | 目标为可识别人物部位或风景组成区域 | 具体部位/类别及实例；先检查本机支持和识别结果，不以“检测成功”代替覆盖检查 |
| 明亮度范围 | 仅处理某一区域中的暗部、中间调或高光 | 范围、过渡平滑度及采样依据；它是亮度筛选，不理解主体，通常结合空间或对象范围 |
| 颜色范围 | 只处理区域中的某种颜色 | 采样位置、颜色容差及空间限制；注意相同颜色出现在无关对象上 |
| 画笔 | 修补边界、细线、局部材质或自动选区不足处 | 路径/范围、大小、羽化、流量与密度；不把粗略框当作精确笔触 |
| 深度范围 | 文件有深度数据且需要按距离筛选 | 深度数据是否可用、距离范围及过渡；视觉上有前后景不代表存在可用深度图 |

## 4. 组合与重叠

先确定基础选区，再按目的添加、减去、相交或反转。组合表达式作为设计说明，执行时必须翻译成真实接口，不能把下列表达式当作 LR API。

- `天空 ∩ 自上向下线性渐变`：天空上部更深，地平线过渡柔和，避免压暗伸入天空的物体。
- `植被 − 主体对象`：收敛环境草地，同时保护主体。
- `对象 ∩ 中暗调明亮度范围`：只改善对象中可恢复的暗部，保护已有反光和最深缝隙。
- `区域粗选 ∩ 青色范围`：降低局部青色干扰，避免影响其他区域的冷色。

明确表达式的括号、组合顺序及反转对象：反转一个组件与反转整个组可能得到不同范围。蒙版是带权重的软选区，不把交集或相减一律当作二值几何运算。

列出可能覆盖同一像素的已有蒙版和新蒙版，以及它们共同影响的参数。全局与局部调整、不同调整组的渲染结果并非可统一按滑块数值线性相加；用合成效果判断是否重复提亮、染色或强化纹理。

## 5. 每个蒙版的设计记录

| 字段 | 内容 |
|---|---|
| `plan_id`、`name` | 本轮稳定标识及可读名称，重试时用来定位而非重复创建 |
| `purpose`、`target_region` | 关联的关键问题、当前差异、目标区域、最终希望出现的关系 |
| `reference_basis` | 参考图观察或推断、证据来源与置信度；无参考也可直接来自用户目标 |
| `action`、`existing_id` | 保留、复用并更新、新建或无需；复用时绑定现有 LR 标识 |
| `selection` | 类型及基础选区；几何、对象提示、采样或类别等必要信息 |
| `combination` | 添加/减去/交集/反转，以及明确的组件关系与顺序 |
| `transition` | 羽化、平滑、密度等适用信息；不套用不同工具的同名刻度 |
| `protect`、`overlap` | 必须排除的区域、与既有/计划内调整的重叠及处理方式 |
| `adjustment_intent` | 提亮、压暗、降饱和、偏暖、保留纹理等方向；下一步再给具体数值 |
| `adjustments` | 本轮当前值、估计增量、最终值、局部单位及实际字段映射 |
| `execution` | 本机功能、连接创建/更新/回读能力、实际执行路径或阻塞项 |
| `checks` | 覆盖范围、边缘、内外方向、重叠效果，以及相对哪些区域应出现何种改善 |

几何设计默认以当前可见裁切画面左上为原点，横向向右、纵向向下，用相对宽高表示；超出画面的延伸需要明确记录。写入前转换到接口坐标并计入裁切、旋转与朝向。参考图和目标图分别定义坐标，不跨图直接复用。

几何与参数先给可用初值及依据，不伪造精度。明亮度范围阈值基于目标区域，记录所用范围刻度；不能直接把 JPEG 灰度分位数当作 LR 范围端点。AI 选区记录提示和生成状态，不仅保存一个假定可跨照片复用的蒙版 ID。

## 6. 对用户展示的方案与执行

风格确认时先说明区域意图，如“加深草地，但保护木围栏的可读性”。确认后、写入前展示精简蒙版表：

| 蒙版 | 范围与组合 | 作用 | 保留项 | 实施方式 |
|---|---|---|---|---|
| 天空层次 | 天空与线性渐变相交 | 收敛上部明度，保留地平线亮带 | 建筑边缘、夕阳过渡 | 复用/更新现有选区或新建；先核对能力 |
| 环境暗调 | 草地区域减去前景主体 | 加深环境、收敛色彩 | 主体细节与远近关系 | 按本图区域设计，不默认全局压暗 |
| 主体细节 | 对象与中暗调范围相交 | 少量恢复纹理可读性 | 反光与深暗缝隙 | 有必要且可实现时才添加 |

上表是设计示例，不代表某张照片已应用。最终方案补齐本图几何/范围和实际数值，不把“待定”直接发送给执行器。

设计完成后按已确认意图执行，不再固定增加一轮蒙版审批。只有主体改变、明显偏离已确认风格或需用户决定的替代方案时才集中提问。不要以“接口尚未实现”为由默默扩大为全局调整或宣称蒙版已执行。

蒙版设计保存为 `edit-plan.json` 的 `mask_plan`；实际操作另存 `masks`，按 [执行计划字段规范](execution-plan.md) 转成当前连接支持的几何、原生主体/天空/背景或 existing 蒙版及局部参数。两者记录稳定 ID 对应关系。`mask_plan` 本身不执行；精细人物部位新建、范围筛选、组合与画笔新建需要交互或其他真实接口，不能只写设计字段便宣称完成。软件界面有某功能，不代表 SDK/连接已暴露此功能。

执行时先复用/创建选区并进行必要的内部覆盖检查，再集中写入局部调整；AI 蒙版需确认已完成计算、非空且没有待更新错误。轮末统一回读并检查 LR 渲染：覆盖和内外方向正确、边缘无光晕、细枝或孔洞无明显误选、重叠不产生过度调整。若接口无法读取覆盖图，不能声称已做像素级验证；必要时将一次集中蒙版叠加查看作为明确说明原因的 GUI 排查，而不是每个滑块截屏。

交付保留可编辑蒙版和真实执行状态；已复用、新建、未实施分别说明，不把推测出来的参考图蒙版当成结果证据。
